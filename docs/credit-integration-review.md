# 재화 기능 통합 검토 — 2026-11-04

`feature/credit`는 팀 `origin/develop`의 `0ccbd3f`를 기준으로 기존 재화 작업 `185cd19`를 옮긴 검토용 브랜치다. 기존 `credit`과 공용 브랜치 이력은 유지했다.

## 통합 시 조정

- 팀의 JPA·Flyway·PostgreSQL·JWT·Security 설정을 유지하고 OpenAPI 의존성을 추가했다. DB·인증 설정을 우회하거나 실제 저장소를 임시 메모리 저장소로 교체하지 않았다.
- 기존 재화 예외 처리기가 다른 Controller의 예외를 가로채지 않도록 CREDIT Controller 범위로 제한했다.
- Controller 결정 전에 발생하는 CREDIT의 404·405·미지원 본문 타입은 별도 라우팅 처리기가 담당한다. 다른 도메인의 라우팅 오류는 기존 공통 처리기에 위임한다.
- OpenAPI 테스트는 실제 웹·보안 설정을 불러오되 DB 자동 설정은 테스트 컨텍스트에서만 제외한다. 운영 설정은 유지한다. 기존 점수 Controller의 입력 오류 응답이 바뀌지 않는 회귀 검증을 추가했다.

## 검증 결과

- JDK 21에서 전체 소스·테스트 컴파일 및 `bootJar` 성공.
- 재화 테스트 49개 통과: 정책 7개, 게임 결과 검증 8개, 정산 서비스 13개, Controller 17개, OpenAPI·보안·다른 도메인 응답 보존 4개.
- 전체 `gradlew test`도 실행했다. 총 80개 중 재화 49개는 통과했고, 기존 앱·인증·매치룸 DB 통합 테스트 31개는 Docker 환경을 찾지 못해 컨텍스트 초기화 단계에서 실패했다. 이 결과를 전체 테스트 통과로 해석하면 안 된다.
- Docker가 있는 환경에서 전체 테스트를 다시 통과시킨 뒤 PR 병합 여부를 검토한다. CI 설정과 DB 테스트를 이번 작업에서 끄거나 변경하지 않았다.

## 팀과 연결할 항목

- 인증 컨텍스트를 읽는 `AuthenticatedUserProvider`, 검증된 게임 기록을 읽는 `GameResultSource`, 원자적 지급을 보장하는 `CreditSettlementStore` 구현과 서비스 Bean 등록은 대기 상태다. 현재 API는 정상적인 미연결 요청에 503을 반환하며 실제 코인을 지급하지 않는다.
- 현재 팀 develop은 PostgreSQL을 사용한다. 저장소 포트는 DB 독립적으로 유지하며 MySQL 전환 여부는 DB 담당자와 별도로 합의한다. Entity·DDL·마이그레이션을 임의로 추가하지 않았다.
- CREDIT의 `/api/credit/v11`과 팀 인증·점수의 `/api/v1`, 공통 오류 응답 및 Security 401 계약은 팀과 정합성을 맞춰야 한다. 기존 엔드포인트·인증 동작을 이번 작업에서 일괄 변경하지 않았다.
- PR 대상은 `develop`이며 실제 지급 연동과 전체 DB 검증이 남아 있음을 명시해 초안으로 제출한다.
